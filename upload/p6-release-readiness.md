# P6: Release readiness (Vercel, Netlify and GitHub)

Project: Private Translator, a browser app that translates on the person's own device. Keep a log in `worklog.md`. Nothing typed or translated may leave the device. This is the last stage. It makes the repository build on Vercel and Netlify with no manual settings, and makes it safe to publish on GitHub under open licenses.

## Plan first

Before changing anything, write a plan in the worklog, no longer than 15 lines: what you will check and change, the logic, the files you will touch, how you will test, and what could go wrong. Think about these in particular:
- What would break in a clean clone on a host that has never seen this project?
- Which files are generated and must not be committed, and which build step produces each one?
- Which license applies to each piece: our code, code we ported, fonts, icons, models, test data?

Then work. If the plan shows this is too big for one sitting, do the first slice and say so.

## Tasks

1. **Clean build.** From a clean clone, `npm ci` then `npm run build` must succeed on a current Node LTS, using the default Next.js build, with no `output: 'export'`, no `vercel.json` and no `netlify.toml`. Actually run it. If the dev server blocks a build, use a temporary copy of the project. If a real build is truly impossible here, say why, and rely on the CI check in task 4. Keep one lockfile, the npm one. Make sure nothing depends on bun.
2. **Generated files.** The worker bundle and the runtime files must be produced by scripts that run automatically (install and build steps), never committed by hand. Confirm a clean clone builds them.
3. **Production only.** Dev only pages, the debug model flag and test harnesses must not exist in the production build. The service worker runs in production only, and its cache is versioned by build id. No server code, API routes, middleware or environment variables.
4. **CI.** Add `.github/workflows/ci.yml` that runs install, lint and build on every push and pull request. It uses only free actions.
5. **First visit weight.** Measure what a first visit transfers, compressed, and list the largest files. The WebGPU build of the runtime loads only when the experimental switch is on. Aim for under 12 MB. Report the number.
6. **Safe to publish.** Add a `.gitignore` for dependencies, caches, generated files, downloaded models and benchmark datasets. Confirm no file in the repository is over 50 MB, and no secrets or keys are present. Keep the benchmark scripts with a short note on how to fetch the data they need, but do not commit the data (FLORES-200 is share-alike licensed).
7. **Licenses.** The app's own code is dual licensed MIT OR Apache-2.0. Add `LICENSE-MIT` and `LICENSE-APACHE`. Add `NOTICE` and `THIRD_PARTY_NOTICES.md`, generated by a script from the dependency tree and run in CI, covering:
   - ported code (IndicTransToolkit, indic-nlp-library, sacremoses, and anything else), with original license headers kept
   - fonts (include the OFL license text)
   - icons and UI libraries
   - every model: its source, its pinned revision, its license, and whether it is non commercial
   Make CI fail if a dependency has a copyleft or unknown license.
8. **README.** Short and plain: what it is, the privacy promise (what is downloaded and from where, and that typed text never leaves the device), how to run it, how to deploy it (import the repository on Vercel or Netlify, no settings), and a license section. The license section must say clearly that the full multilingual model (NLLB-200) is licensed for non commercial use only, and list the other models and their licenses.
9. **Failure behaviour.** Check that a clear message appears if the Hugging Face host can't be reached, and if browser storage is blocked.

## Done when

A clean clone builds, CI is in place, the first visit weight is reported, the repository is safe to publish, and the license files, notices and README are written.

## Report (short)

Your plan in three lines, the build result, the first visit weight, the license summary, anything that failed, and any decision you made yourself.

## Do not

Add `vercel.json` or `netlify.toml`. Commit models, datasets or generated files. Add a dependency with a copyleft license.
